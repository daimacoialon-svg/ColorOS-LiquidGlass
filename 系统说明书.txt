ColorOS-LiquidGlass V1.9.205.288.28｜Kyant Dock 可见边界修正实验版
========================================================
基于 V1.9.205.288.27。只修改 Dock 光学胶囊的水平几何计算，不更改文件夹光学管线、Kyant Shader、Dock 图标布局、原有设置键或实际材质参数。

修复目标
V288.27 真机截图中，Dock 左边圆角可见、右边胶囊越过屏幕边缘被裁掉。
根因假设：Hotseat 的 View 宽度 / 屏幕 X 位置不等于实际可见窗口区域；旧版仅按 Hotseat 宽度减去 3.5% 内边距，未考虑右侧可见屏幕边界。

本版修正
1. 新增 horizontalGlassBounds()：优先保留旧 Dock 原有 3.5% 水平内边距和圆角比例，但按真实窗口/根视图交集计算左右最大可见边界；窗口左右额外保留 max(10dp, 3.5%窗口宽度) 的安全边距。
2. 将计算得到的最终屏幕坐标转换回 Hotseat 的局部 Compose 坐标，避免把屏幕坐标直接当局部像素使用。
3. 壁纸 sampleX 使用修正后实际玻璃左边界，防止外观位置改正后采样纹理出现水平错位。
4. 当窗口/Hotseat 几何无效时不绘制越界胶囊，不影响 Hotseat 图标触摸。
5. 首次成功读取窗口/Hotseat 几何时输出一次 KYANT28828_DOCK_GEOMETRY 日志（非逐帧），可以核对尺寸是否正确。

未修改
Kyant 文件夹效果、Dock 全部图标位置、三项统一材质滑块、Dock/文件夹独立开关、V288.27 的诊断自动关闭预设和原生 Drawable 回退。

编译与测试
Android Studio 打开顶层目录，执行 :liquidglass-module:assembleDebug。开发容器没有可用的 Gradle 9.7.1 分发包，因此尚未通过 Android 编译和真机验证。
真机请观察：Dock 左右各留相似安全边距、左右圆角完整、折射与壁纸纹理贴合、图标仍居中且可点击；横竖屏/桌面启动/锁屏返回后尺寸是否稳定。
如果仍然不对，抓取 Vector 日志中 KYANT28828_DOCK_GEOMETRY 行以检查真实 Hotseat 宽度和屏幕窗口边界。
关闭 Dock Kyant 可通过 UI 独立开关，或 Termux:
  su -c settings put global liquidglass_kyant_dock_28827 0
  然后重启 Launcher，回退旧 Dock Drawable。

前版 V288.27 接入信息（保留供参考）
ColorOS-LiquidGlass V1.9.205.288.27｜Kyant0 文件夹 + Dock 光学接入版
========================================================
适用：OnePlus 13T / ColorOS 15 / Android 15 / KernelSU / LSPosed Vector。
工程：liquidglass-module（Android Studio Gradle 多模块工程），包含 Kyant0 AndroidLiquidGlass kmp 源码与现有 ColorOS 适配。

本次已实现的源码修改
1. 新增 KyantDockLens28827.kt：为 Hotseat 创建独立 Compose 光学宿主。该宿主作为 Hotseat 同父容器内的前置兄弟 View（绘制顺序在 Hotseat 图标下方），不接管触摸，不把 Compose View 添加到 OEM CellLayout 内。
2. Dock 使用 Kyant layerBackdrop / drawBackdrop / lens / blur / Highlight 实际光学调用；参考帧通过既有 KyantLauncherFrameBridge266 获取，以 Hotseat 自身实际屏幕位置采样；保持旧版 3.5% 水平内边距、30% 角半径比例和原生 Dock 图标位置。
3. 父容器不是 FrameLayout、壁纸参考帧尚未准备或宿主初始化异常时，保留旧 DockBackground204 渲染而非覆盖图标；Compose 异常时恢复原 Dock 背景。
4. 新增 KyantOptics28827.kt：文件夹与 Dock 统一读取三项 Settings.Global 并通过 ContentObserver 监听更新，Compose State 驱动实时重绘。
5. MainActivity UI 将文件夹与 Dock 的 Kyant 开关、折射强度（0–200%，默认100）、模糊半径（0–20dp，默认0）和高光透明度（0–100%，默认100）放在同一个设置区域。设置通过 Root 写入并回读验证；开关分别持久化，不强制同时开启。
6. 开启任一 Kyant 开关时写入经真机确认的 pipeline=-1、display_isolation=0、native_layer=0、native_bridge=0、motion_ab=0，连同其它冲突对照、图层与高频日志诊断开关归零。
7. 保留 V288.26 文件夹主渲染框架和旧 Dock Drawable；不再使用有掉帧问题的 Bitmap 桥接作为正常路径。

新增全局参数
  liquidglass_kyant_dock_28827                  0关闭 / 1开启 Dock Kyant
  liquidglass_kyant_optical_strength_28827      0–200，默认100
  liquidglass_kyant_optical_blur_28827          0–20 dp，默认0
  liquidglass_kyant_optical_highlight_28827     0–100，默认100
原有文件夹开关仍为 liquidglass_kyant_persistent_probe_2884。
独立开关切换后建议通过 Vector 重启 Launcher；上述三个材质参数由 Launcher ContentObserver 响应，可实时调整。

构建
  使用 Android Studio 打开顶层文件夹，先同步 Gradle，再执行 :liquidglass-module:assembleDebug 或 assembleRelease。
  构建所需 Gradle 9.7.1、Android Gradle Plugin 9.3.2、Android SDK compileSdk 37 及 Kotlin/Compose 依赖。
  本次工作容器不能访问 Gradle 分发服务器，未能完成 Android APK 编译；源码未在真机验证，不应视为稳定发布。

测试顺序
1. 先备份当前 V288.26 稳定 APK/模块；如遇启动异常，可用 Root 关闭两项全局 Kyant 开关再重启 Launcher。
2. 只开启文件夹 Kyant，确认之前验证成功的折射仍然正常。
3. 开启 Dock Kyant，重启 Launcher，确认出现真实折射，Dock 图标可点击且圆角、尺寸不变化。
4. 分别关闭文件夹和 Dock Kyant，确认相互独立；Dock 关闭后恢复旧 DockBackground204。
5. 测试三项材质滑块，观察文件夹与 Dock 的同向实时变化；进行左右滑动、松手、翻页和壁纸更换测试。
6. 如果日志出现 KYANT28827_DOCK_PARENT_UNSUPPORTED 或 KYANT28827_DOCK_REFERENCE_NOT_READY，说明本机当前 Hotseat 结构或参考帧不满足接入条件，旧 Dock 会回退，不能把回退画面误当成 Kyant 光学效果。

异常回退（Termux）
  su -c settings put global liquidglass_kyant_dock_28827 0
  su -c settings put global liquidglass_kyant_persistent_probe_2884 0
  然后通过 Vector 重启 Launcher。
